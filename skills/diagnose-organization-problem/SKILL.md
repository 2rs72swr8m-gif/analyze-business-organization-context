# 判断是否为组织问题

## 目标

在进入组织设计之前回答两个连续问题：

1. 组织系统是否是当前经营或管理症状的实质性原因；
2. 如果问题与组织有关，是否必须调整组织结构，还是用更小的机制修复即可。

把“协同差、效率低、职责不清、决策慢”等表述当作待解释症状，不直接当作组织结论。优先选择能够解决问题的最小干预，不把重画组织图作为默认答案。

## 核心边界

区分三个层次：

- **经营或管理症状**：结果、体验或事件，例如收入下滑、项目延期、审批缓慢、客户投诉或部门冲突。
- **组织系统问题**：组织边界、责任、权力、资源、协同、绩效或正式与非正式运行方式持续制造问题。
- **结构调整需要**：现有单元划分、汇报关系、管理层级或治理边界本身构成主要约束，且较小的机制修复不足以解决。

组织相关不等于必须改结构。权责表、决策阈值、流程、会议、绩效指标、人才能力和领导行为都可能在不调整组织图的情况下修复问题。

完整读取 [diagnostic-logic.md](references/diagnostic-logic.md)，使用其中的竞争性解释和决策门槛。完整读取 [cards-and-output.md](references/cards-and-output.md)，建立证据卡、诊断卡和最终输出。

## 工作流程

### 1. 确认真实决策问题

正式诊断前简短确认：

- 出现了什么具体症状，影响了哪个经营、客户、效率、创新、质量或风险结果；
- 诊断对象是哪一个企业、业务单元、区域、职能、团队或组织界面；
- 问题从何时开始，发生频率、范围和严重程度如何；
- 管理者当前考虑采取什么动作，要做出的真实决定是什么；
- 哪些战略、产权、监管、技术、人才或时间条件不可改变；
- 用户是否有访谈、会议纪要、制度、流程、经营数据、组织数据或已有分析可提供；
- 材料是否存在保密或公开输出限制。

若材料不足，允许先做初步假设地图，但必须标记“未形成诊断”，并列出最低补充证据。不要用模型常识补写目标企业事实。

### 2. 把混合材料拆成原始证据卡

先提取最小事实单元，再做诊断。每张原始证据卡至少记录：

| 字段 | 内容 |
|---|---|
| 证据编号 | 稳定、可引用的编号 |
| 原文或事实 | 原话、数据、事件或制度要求 |
| 来源与日期 | 文件、人员、会议或数据系统及时间 |
| 涉及组织 | 证据涉及哪些组织对象 |
| 组织角色 | 谁承担结果、提出要求、做决定、提供资源、执行或被影响 |
| 可观察现象 | 发生了什么，不提前写原因 |
| 业务影响 | 对客户、收入、成本、速度、质量、风险或人员的影响 |
| 核实状态 | 已确认、待核实或排除 |

原始证据卡只保存信息，不标“强证据、中证据、弱证据”，也不直接标记“属于组织问题”。同一事实可能支持一个组织的诊断、限制另一个诊断，或只作为背景。

### 3. 建立组织对象地图

列出证据中的组织对象及其关系：

- 企业、总部、业务单元、区域、职能、项目或外部伙伴；
- 各自承担的经营结果、专业责任和风险责任；
- 正式汇报、资源供给、决策和协同关系；
- 证据中只是被提及、还是拥有独立事实。

围绕每一个组织分别诊断。某组织出现在其他组织的证据中，不代表它自身已经形成问题诊断。

### 4. 把症状展开为竞争性假设

至少比较以下解释，不允许只保留“结构问题”：

1. 外部环境或资源约束；
2. 战略和优先级不清或频繁变化；
3. 运营模式、组织边界或结构不适配；
4. 治理、权责和决策机制失配；
5. 流程、会议、信息和系统运行失效；
6. 领导、人才、专业能力或资源不足；
7. 目标、绩效、激励或资源分配冲突；
8. 执行纪律、个体行为或人岗匹配问题。

对每项假设写出它能够解释的现象、不能解释的现象、支持证据、反向证据、例外和下一步验证方式。

### 5. 建立“组织 × 候选问题”诊断卡

只对有独立证据的组织建立诊断卡。逐条评价：

- 与候选问题直接相关、间接相关还是不相关；
- 在当前组织和情境中是否有效；
- 对假设起支持、反向、例外还是背景作用；
- 是否存在同样合理的替代解释；
- 还缺什么经营数据、制度、流程记录、决策样本或访谈。

诊断强度属于“组织 × 候选问题”的最终判断，不属于单张证据：

- **强**：多个独立来源相互印证，并有制度、流程记录或数据支持；关键反证不足以推翻。
- **中**：存在直接证据并影响经营结果，但仍有重要缺口、例外或替代解释。
- **弱**：主要来自单一观点、间接现象或少量事件，只能保留为待验证假设。
- **未形成**：缺少足够的组织专属证据，或现有证据无法区分主要解释。

### 6. 通过两道决策门形成结论

#### 决策门一：这是否是实质性组织问题

综合检查：

- 问题是否跨人员、跨事件或持续发生，而不是一次偶发失误；
- 是否可以追溯到责任、权力、资源、组织边界、协同或激励的系统安排；
- 是否影响关键价值流、客户、经营结果或风险；
- 是否已经检验战略、流程、能力、领导和执行等替代解释；
- 调整组织系统是否有可能改变结果。

#### 决策门二：是否需要调整结构

只有同时满足以下条件，才建议进入结构方案设计：

- 主要矛盾来自组织单元边界、汇报关系、层级、管理跨度或治理边界，而不只是机制未执行；
- 现有责任与权力冲突具有结构性，无法通过澄清职责或决策规则稳定解决；
- 更小的流程、权责、绩效、人才或领导干预不足以消除关键约束；
- 结构调整的收益高于协同成本、迁移风险和能力缺口；
- 目标组织具备必要的领导、人才、数据、系统和治理条件。

证据达不到门槛时，不建议重画组织图。提出验证计划或较小干预，并说明什么结果会触发下一步结构设计。

### 7. 推荐最小充分干预

按干预强度由低到高选择：

0. 不采取组织动作，继续观察或修正问题定义；
1. 澄清目标、角色、责任或执行要求；
2. 修复权责、流程、会议、绩效、激励、数据或协同机制；
3. 调整局部岗位、团队边界、汇报关系或管理层级；
4. 进入完整组织结构或治理模式重设计。

默认选择能够解决主要因果机制的最低层级。若推荐试点，明确范围、周期、指标、失败条件和升级到结构调整的触发器。

## 默认交付

输出一份可供管理者决策的诊断摘要，至少包括：

1. **决策问题与范围**；
2. **症状及业务影响**；
3. **组织对象地图**；
4. **原始证据卡清单**；
5. **竞争性假设比较**；
6. **按组织诊断卡与强度**；
7. **两道决策门结论**：是否为组织问题、是否需要结构调整；
8. **最小充分干预建议**；
9. **内部验证问题、指标和触发条件**；
10. **证据限制与不确定性**。

结论使用以下格式：

> - **当前判断**：是 / 部分是 / 暂不支持 / 未形成诊断。
> - **组织问题强度**：强 / 中 / 弱 / 未形成。
> - **是否需要结构调整**：需要进入设计 / 先做局部验证 / 优先机制修复 / 暂不建议。
> - **主要依据**：列出直接证据、反证和关键替代解释。
> - **下一步**：给出最低成本的验证或干预动作及升级条件。

## 质量检查

- 是否把症状与原因分开；
- 是否先确认真实经营影响和管理决策；
- 是否把材料拆成可追溯的原始证据卡；
- 原始证据是否保持无强度、无诊断标签；
- 是否围绕每个组织分别建立诊断；
- 是否至少保留一个非组织结构解释和一项反证；
- 是否区分组织相关与需要结构调整；
- 是否选择最小充分干预，而非默认重画组织图；
- 是否允许“未形成诊断”；
- 是否列出能够推翻当前判断的新证据和升级条件；
- 是否遵守内部材料的保密和公开限制。

## 保密与表达

- 不把用户内部材料、访谈原话或未公开组织信息写入公开版本，除非用户明确授权。
- 不披露私人信息和未公开的人事评价。
- 使用“事实显示、初步判断、替代解释、待验证”区分证据层级。
- 默认输出 Markdown；除非用户明确要求，不扩展为完整组织设计方案。
