# 证据卡、诊断卡与输出模板

## 一、原始证据卡

```markdown
### E-001

- 原文或事实：
- 来源与日期：
- 涉及组织：
- 组织角色：结果承担者 / 决策者 / 资源提供者 / 执行者 / 被影响者 / 背景方
- 可观察现象：
- 业务影响：
- 核实状态：已确认 / 待核实 / 排除
- 备注：
```

不要在原始证据卡中加入诊断强度。访谈观点可以是有效的“感知事实”，但不能自动成为因果事实。

## 二、组织对象卡

```markdown
### O-001｜组织名称

- 正式定位：
- 主要结果责任：
- 关键决策权：
- 关键资源：
- 与其他组织的关系：
- 独立证据编号：
- 仍待确认：
```

没有独立证据的组织可保留为关系对象，但不生成其自身问题结论。

## 四、按组织诊断卡

```markdown
### D-001｜组织 × 候选问题

- 组织对象：
- 候选问题：
- 组织问题类型：结构 / 治理权责 / 运行机制 / 能力 / 激励 / 领导执行 / 复合
- 诊断判断：
- 诊断强度：强 / 中 / 弱 / 未形成
- 直接业务影响：
- 主要替代解释：

| 证据 | 相关性 | 有效性 | 作用 | 理由 |
|---|---|---|---|---|
| E-001 | 直接 / 间接 / 无关 | 强 / 中 / 弱 | 支持 / 反向 / 例外 / 背景 |  |

- 当前证据不能支持：
- 待补充信息：
- 可推翻本判断的证据：
```

表中的“有效性”只表示该证据在当前组织与候选问题中的诊断作用，不是原始证据的固有强弱。

## 五、决策摘要

```markdown

- 是否需要结构调整：需要进入设计 / 先做局部验证 / 优先机制修复 / 暂不建议
- 最小充分干预层级：0 / 1 / 2 / 3 / 4

- 支持证据：

|---|---|---|---|---|---|

## 6. 待验证问题

- （待填写）

```

## 六、写作要求

- 先给当前判断，再说明依据和不确定性；
- 用事实和机制代替“加强协同、提升敏捷”等空泛表述；
- 明确哪些结论可执行，哪些只是待验证假设；
- 不把管理者观点写成全公司事实；
- 不因证据数量多而忽略证据是否独立；
- 不用百分比分数伪装诊断精度。
